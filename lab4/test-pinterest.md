# План тестирования веб-приложения Pinterest

## 1. Цель
Удостовериться, что основные функции Pinterest работают корректно, интерфейс удобен и адаптивен, данные защищены, а система стабильна при высоких нагрузках.

## 2. Объект тестирования
Веб-сайт, позволяющий: регистрироваться/входить, создавать пины (изображение + описание + ссылка), организовывать доски, искать и фильтровать контент, просматривать ленту рекомендаций, ставить лайки, комментировать, подписываться, настраивать профиль.

## 3. Виды тестирования и их обоснование

* **Функциональное тестирование**.
Проверка всех сценариев работы: регистрация, авторизация, создание и редактирование пинов/досок, поиск, фильтры, валидация полей ввода, поведение кэша и cookie, обработка ошибок. Сюда же включены проверки через DevTools (отсутствие ошибок в консоли, корректная загрузка стилей и изображений).

* **UI/UX и кросс-платформенное тестирование**.
Оценка соответствия макетам, адаптивности на разных разрешениях, удобства навигации, читаемости текстов, корректного отображения длинных строк (многоточие), плейсхолдеров, скролла, доступности с клавиатуры. Проверка в актуальных версиях Chrome, Firefox, Safari, на мобильных устройствах.

* **Тестирование безопасности**.
Проверка защиты от XSS, SQL-инъекций, перебора паролей (лимиты попыток), безопасности сессий (куки с флагами Secure, HttpOnly), правил доступа к закрытым доскам, обязательного использования HTTPS для конфиденциальных данных.

* **Нагрузочное тестирование**.
Оценка производительности при большом числе одновременных пользователей: стабильность ленты, поиска, загрузки изображений. Критически важно для сервиса с визуальным контентом и рекомендательной системой.

## 4. Стратегия тестирования

* Ручное тестирование по детальному чек-листу (основанному на рекомендациях из статьи, плюс специфические для Pinterest проверки).
* Автоматизация основного пользовательского пути (Selenium/Cypress): авторизация → создание пина → поиск → сохранение в доску.
* Безопасность: сканер OWASP ZAP + ручные проверки по OWASP Top 10.
* Нагрузочное тестирование: инструмент JMeter, моделирование сценариев до 2000 одновременных пользователей.
* Кросс-браузерное тестирование: BrowserStack + реальные устройства.

## 5. Критерии входа и выхода

* *Вход:* развёрнут тестовый стенд, стабильная сборка, тестовая база данных, готовы моки внешних сервисов (OAuth-авторизация, загрузка файлов).

* *Выход:* все запланированные тесты выполнены, критические и блокирующие дефекты закрыты, среднее время отклика ленты при нагрузке 500 пользователей ≤ 1 секунда, 0% ошибок на ключевых сценариях, корректное отображение во всех целевых браузерах и на мобильных устройствах.

## 6. Примеры тест-кейсов

### Функциональное тестирование

1. *Создание пина (позитивный сценарий)*

* Залогиниться, нажать «+», загрузить JPEG до 10 МБ, ввести описание (до 500 символов) и валидную ссылку, выбрать доску, сохранить.

* Ожидаемый результат: пин отображается на выбранной доске, изображение не искажено, описание сохранено, ссылка активна, в консоли DevTools нет ошибок.

2. *Валидация полей регистрации*

* Попытаться зарегистрироваться с email без символа «@», с паролем короче 6 символов, с пустыми обязательными полями.

* Ожидаемый результат: система отображает понятные сообщения об ошибках, обязательные поля подсвечены, отправка формы блокируется, астериски (*) видны у всех обязательных полей.

3. *Поведение сессии и cookie*

* Войти в аккаунт, скопировать URL страницы профиля, затем выйти из системы, удалить все cookie браузера, перейти по сохранённому URL.

* Ожидаемый результат: доступ к профилю запрещён, происходит редирект на страницу входа.

### UI/UX-тестирование

1. *Мобильная адаптивность (iPhone 12, 390×844)*

* Открыть главную страницу, проверить отображение ленты, карточку пина, кнопку «Сохранить».

* Ожидаемый результат: нет горизонтальной прокрутки, все интерактивные элементы размером не менее 44×44 px, текст не наезжает на изображения, есть плейсхолдеры в полях ввода.

2. *Длинное название доски*

Создать доску с названием из 80 символов.

Ожидаемый результат: название обрезается многоточием в общем списке, при наведении/клике показывается полностью, вёрстка не нарушена.

### Тестирование безопасности

1. *Защита от XSS в поиске*

* Ввести в поле поиска ```<script>alert(1)</script>```, нажать «Найти».

* Ожидаемый результат: скрипт не выполняется, введённый текст отображается как обычный запрос или экранируется, сообщение «Ничего не найдено» (если нет релевантных результатов).

2. *Перебор пароля и временная блокировка*

* Ввести неверный пароль для существующего аккаунта 5 раз подряд.

* Ожидаемый результат: после 5-й попытки появляется капча или сообщение о блокировке на определённое время, дальнейшие попытки отклоняются.

3. *Доступ к чужой секретной доске*

* Пользователь А создал секретную доску, пользователь Б (не подписчик) пытается открыть её по прямому URL.

* Ожидаемый результат: отображается страница с ошибкой доступа или 404, в поиске пользователя Б эта доска не индексируется.

### Нагрузочное тестирование (один сценарий)

* *Поиск и просмотр ленты под нагрузкой*

  * 1500 виртуальных пользователей одновременно выполняют поисковые запросы и прокручивают ленту в течение 5 минут.

  * Ожидаемый результат: среднее время ответа не превышает 800 мс, количество ошибок менее 0,1%, все изображения загружаются без существенных задержек.
